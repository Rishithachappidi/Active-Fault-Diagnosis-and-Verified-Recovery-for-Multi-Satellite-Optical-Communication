Satellites can send data to each other with lasers. The beam is so narrow that at 800 km, a pointing error of 20 microradians moves the spot about 16 metres.

When received power drops, re-pointing looks like the fix. But the beam may be misaligned, the transmitter weaker, the path blocked, or the angle sensor wrong, and re-pointing only helps with some of these. So we ask three questions: is something wrong, what is wrong, and can the link come back? We compare our first supervisor (V1) with a revised one (V2).

V1's low score for naming the fault wasn't a tuning problem. Its code could only ever name one fault type, optical power loss. 66% on that one and 0% on the other six averages to 9.5%.

Two rows got worse. V2 recovers fewer outages because it prevents five sensor-fault outages altogether, and what's left is harder to fix. With 82% power loss, even perfect pointing only gives 0.70 µW against the 1.5 µW needed. V2 names those faults and reroutes traffic instead of pretending to repair them. It also raises its first alarm later, because it waits for evidence, and it now gives a few false alarms around actuator faults that V1 never noticed at all.

How V2 tells faults apart

Four checks, each using information V1 ignored.

Sensor or beam?

A separate rate sensor measures how fast the terminal turns. V2 adds that up into its own angle estimate. If the angle sensor suddenly disagrees with it, the sensor is wrong, not the beam.

Weak or slow actuator?

V2 compares the torque it asks for with the torque it gets over the last 0.8 s. It fits how much arrives and how fast. A weak actuator and a slow one change different numbers.

Misaligned or dim?

When the cause is unclear, V2 nudges the beam a few microradians each way. If power rises in one direction, the beam is off target. If it falls everywhere, the light is weaker.

Is the fix still right?

V2 keeps predicting the power its explanation implies. If the measurements disagree twice in a row, it drops the correction and checks again. That fixed most outages after a fault cleared.

What it can't do

  • Tell a blocked link from a dead transmitter. Both look completely dark.
  • Catch a sensor bias that was there from start-up, without calibration.
  • Work without accurate torque measurements, which real hardware may not have.
  • Handle moving satellites, several faulty links at once, or realistic traffic. The network is fixed and traffic is a steady flow.
  • Say anything about real satellites. This is all simulation.

Running the MATLAB version

You need MATLAB R2026a with Simulink. From the project folder:

start_v2                  % opens the 4-satellite model
test_v2                   % runs the nine checks
folder = run_v2_suite;    % runs all 320 comparison trials
plot_v2_comparison(folder)
